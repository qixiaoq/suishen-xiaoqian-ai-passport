# 手机解读服务

设备热点的 `192.168.4.1` 页面只用于把 AI Passport 接入日常 Wi-Fi；它不是解签服务。配网后手机会回到正常网络，解签二维码仍需指向下面这项可访问的手机服务。

设备二维码只携带本次玩法的简短数据。手机扫码后，服务创建 30 分钟的临时会话，并把访客填写的问题交给兼容 OpenAI Chat Completions 的 AI 接口。用户主动点击“保存本次”时，解读才会保存在当前浏览器。

## 本地启动

```sh
cd companion
npm ci
AI_API_BASE_URL=https://api.example.com/v1/ AI_API_KEY=your-key AI_MODEL=your-model npm start
```

默认端口是 `8787`。同一 Wi-Fi 下做真机测试时，可把开发电脑的局域网 IP（例如 `http://192.168.1.10:8787`）填入 `APP_BASE_URL` 和固件的 `CONFIG_XIAOQIAN_COMPANION_URL`，并保持电脑服务运行。手机不能使用电脑的 `localhost`。要让朋友在其他网络下扫码，需将本服务部署在可访问的公网 HTTPS 地址，并把同一地址写入上述两处；固件地址末尾不要加斜线。

公开源码中的 `CONFIG_XIAOQIAN_COMPANION_URL` 默认为空，不包含开发者的局域网地址。构建个人版前先设置实际服务地址；未设置时，设备会明确提示“请先配置手机解读服务地址”。已经烧录在设备中的旧版不会因源码默认值变化而改变。当前本机 `/setup` 只用于开发测试，服务重启后需重填密钥；发布给其他人使用前应设计公开服务的密钥管理、费用限制和访问控制，不能把自己的 API Key 放入固件、网页代码或仓库。

本机测试也可以先只运行 `npm start`，然后在**运行服务的电脑**打开 `http://127.0.0.1:8787/setup`，填写兼容 Chat Completions 的 HTTPS 接口地址、模型名和 API 密钥。密钥只保存在服务进程内存中，不会写入固件或项目文件；重启服务后需要重新填写。手机扫描二维码后刷新签卦页，白话解读按钮才会启用。没有配置时，手机页会直接显示原因。

目录内提供 `Dockerfile` 便于容器部署。三项 AI 环境变量与 `APP_BASE_URL` 应在托管平台的密钥或配置项中设置，不要把 API 密钥打进镜像。

`DEVICE_TOKEN` 仅用于可选的 `POST /api/sessions` 设备直连接口。当前设备二维码使用 `/q/` 路径，不要求设备直接访问解读服务。公开部署前应在反向代理上配置请求频率限制，因为扫码入口无需账号即可创建会话。

黄历、农历与生辰排盘由 MIT 许可的 `lunar-javascript` 1.7.7 计算。时间起卦也使用它计算出的农历日期。解读属于传统文化体验，不应被当成确定预测。
